# Findings

- Reproduction: OSMD `graphic.MeasureList` has eight outer entries for eight measures. Each outer entry contains one `GraphicalMeasure` per staff; the two source parts were identified by `GraphicalMeasure.ParentStaff.ParentInstrument.IdString` values `P1` and `P2`. Treating the outer index as part index tagged only two of sixteen lyric nodes and could associate later measures with the wrong track.
- Repair: traverse measure first, then staff. Resolve generated part IDs (`P1`, `P2`, ...) to model track order, with a staff-index fallback only when the number of staves equals the number of model parts. Part labels now come from OSMD `MusicSystem.Labels[].SVGNode`; this avoids scanning lyrics or score text by matching visible strings.
- Added an eight-measure, two-part OSMD fixture with same-pitch, same-text notes at each measure start. It checks all 16 labels, their exact source part/index per graphical measure, and a part name that is identical to lyric text.
- Stabilized generated MusicXML note IDs with output part, voice, note ordinal, measure, and duration-component identity. This keeps IDs unique for ties split across measures and also for duplicate references that reuse source indices. The numbered-score parser accepts the expanded ID while retaining source note indexes.
- Focused Node tests pass: 24 passed, two skipped (optional local SVP samples and Playwright package). Edge browser fixtures pass for the staff source mapping and the 102-measure jianpu renderer. Running every score `*.test.js` in this worktree hits three unrelated dependency failures because `vue-i18n` and `pinyin-pro` are not installed here; no dependency install was attempted.
